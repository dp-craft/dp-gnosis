## Method

Every factual claim that could be checked was checked against the repository: file line numbers, symbol locations, line counts, and whether a named command or environment variable actually exists. Findings were then de-duplicated across runs so that "unique finding" means *no other run surfaced it*.

Two caveats stated up front. **F is my own output**, so its scores are self-assessed and should be read with that discount. And the ten pre-existing runs were produced under settings I cannot inspect — the labels in the filenames are taken at face value.

## Consensus — what all six agreed on

Four findings appeared in all eleven runs, which is the strongest signal in the whole comparison:

1. **Install friction.** Not on npm; `npm pack` + global tarball install is a bounce point.
2. **No demo corpus.** A fresh clone searches nothing and exits 0 — correct by design, surprising in practice.
3. **Density before first success.** Exit-3 semantics, the two-gate rule and PRF defaults arrive before the user has run anything.
4. **`packages/gnosis/README.md` is a reference manual, not a tutorial**, and no tutorial exists.

Nine of eleven flagged the **`ingest` → `index` two-command trap** — G and K are the two that never raise it, a genuine omission given the README warns about it explicitly. Both are qwen3.8 runs that went to the source: reading code appears to pull attention away from the warnings the docs already carry. Ten of eleven also asked for a demo/example corpus and a progressive-disclosure restructure of the root README. That convergence is worth acting on regardless of which run one trusts most.

## What the settings actually changed

**Source access beat reasoning effort, and G is the clean proof.** G ran at *normal* effort with both source access and web research, and produced the most accurate document of the seven in the fewest words — 46 lines, 816 words, zero wrong claims, two defects nobody else found. C ran at *normal* effort and produced the highest evidence density of the first five — twelve verified code citations, and the only findings that required reading source (`enrich`, the absolute-path guard, `DP_GNOSIS_DATA_HOME`). Its prose is the weakest of the six, dropping articles and reading like field notes, but the claims underneath are the most defensible. Tool access moved quality more than effort level did.

**xhigh helped one model and hurt the other.** B (muse, xhigh) is a clear step up from A (muse, default): deeper structural argument, better organised recommendations, more insight per claim. E (qwen, xhigh) reads better than D (qwen, normal) — crisper headers, better closing assessment — but it dropped citation discipline (2 doc citations against D's 14), invented a line count, and produced one recommendation that cannot work. Higher effort bought fluency on the qwen side and rigour on the muse side.

**Fluency and grounding traded off — except in G.** Ranking by prose quality gives G ≈ E > B > F > A > C > D. Ranking by evidence gives G > C > F > A ≈ D > B > E. G is the only run that tops both lists; C and F sit in the top half of both by different routes — C by citing code, F by citing code *and* naming the external standard it measures against. G does all three: code, external standard, and a verdict paragraph written for a human.

**Model capability dominated every other lever, and quantisation barely mattered.** qwen3.8 takes the **top three places across three different quant/effort combinations** — G 29 (q6, normal), J 28 (q6, xhigh), K 27 (q4, medium) — while qwen3.6 q4 takes **last and joint-eighth** (D 17 normal, E 21 xhigh). K is the decisive data point: at the *lowest* settings of any qwen3.8 run — q4 weights, medium effort — it still beat every muse configuration and both qwen3.6 runs, with zero errors. The generation gap between qwen3.6 and qwen3.8 was worth about ten points; dropping qwen3.8 from q6/xhigh to q4/medium cost one.

**For qwen3.8, xhigh bought scope and cost compliance.** J (xhigh) reviewed six user-facing docs *plus* `.claude/skills/`, invented a three-persona structure, and attached evidence to every finding — but dropped the external-research step that G (normal) performed. G is more concise and did what the prompt asked; J covers more ground and found the one consumer path nobody else looked at. They are effectively co-leaders separated by one criterion.

**Prompt detail bought grounding; source access bought a different class of finding.** H and I are the same model at the same effort with no source access, separated only by how detailed the prompt was — and the gap is the cleanest result in the comparison:

| | H (strict) | I (strict + detailed) |
|---|---:|---:|
| Words | 532 | 1095 |
| Document citations | 0 | **19** |
| Grounding | 2 | **4** |
| Depth | 2 | **4** |
| Total | 21 | **26** |

A more detailed prompt made the model *cite what it had read*, doubling grounding with no new tools. But no amount of prompt detail produced the code-vs-doc drift findings that C and G reached by reading `src/` — the omitted `init`/`doctor` rows and the six-vs-five contradiction are simply not visible from the documents alone. The two levers buy different things and do not substitute for each other.

**A strict prompt alone bought process compliance, not evidence.** H is the cleanest natural experiment in the set: same base model as A/B/C, normal effort, no source access, but a prompt that pinned the method. It is the only run with a dedicated research-summary section naming the standards it measures against — precisely the step the original prompt asked for and that C, at 1/5 on research, skipped entirely. But it produced **zero citations**, and its nine gaps are almost all consensus items other runs had already reached with evidence attached. Comparing H against C, both muse at normal effort: **source access moved quality far more than bare prompt strictness did**, while prompt strictness fixed the one thing source access left undone. G is what having both looks like — and I shows how far a detailed prompt gets on documents alone: it is the **best run in the field that never opened a source file**, beating its own xhigh sibling B by 26 to 24.

**Transcription is not analysis.** D spends about half its length quoting the README back. It is accurate and it is readable, but a reader who has the README open learns least per line from it.
