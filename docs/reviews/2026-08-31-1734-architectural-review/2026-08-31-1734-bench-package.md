# Architectural review — `packages/gnosis-bench`

**Scope**: `packages/gnosis-bench/src/**/*.ts` (35 files, 14 068 lines excluding tests) + `datasets.json`. The engine (`packages/gnosis/src`) is reviewed ONLY at the seam.
**Method**: `grep -n "^export"` for structure, `Read` for behaviour, `npx eslint` for measured style debt. Every claim below cites a file and an exported symbol.
**Date**: 2026-08-31. **Tree**: `main` @ `146bbb2`, clean.

## Findings by severity

### HIGH

#### H1 — The seam is documented as single and is not. `engine.ts` (docblock), `run.ts`, `report.ts`, `compare.ts`, 7 others

`packages/gnosis-bench/src/engine.ts` opens with *"THE SEAM: the benchmark's only contact with dp-gnosis"*, and `handbook/GNOSIS-GUIDE.md` § Pick your door routes "change how the bench touches the engine" there. Measured:

| | Files | Distinct engine modules imported |
|---|---|---|
| via `engine.ts` | 1 | 15 |
| bypassing it | **10** | **15** |

The bypassing files are `run.ts`, `report.ts`, `compare.ts`, `corpus.ts`, `chartData.ts`, `forensicsCli.ts`, `vocabGapCli.ts`, `enrichmentGate.ts`, `deterministicEnrichment.ts`, `fetch/vault.ts`. Several reach past the engine's public surface into internals:

- `run.ts` imports `fusesLegs` from `../../gnosis/src/adapters/lanceDbDenseAdapter.js` and `fitToTokenBudget` from `../../gnosis/src/budget.js`
- `deterministicEnrichment.ts` and `vocabGapCli.ts` import `FTS_TABLE` / `readIndexAnalyzer` / `fts5VocabularyGap` from `../../gnosis/src/adapters/`
- every import is a deep relative path (`../../gnosis/src/...`), never the engine barrel `packages/gnosis/src/index.ts`

**Why it matters.** The seam's stated purpose is that the engine could be swapped behind it and the suite would still measure the real thing. Today it could not: an engine refactor that moved `fts5Adapter`'s table name, `budget.ts`'s export, or `cli/adapter.ts`'s `DENSE_ROUTES` breaks the bench in ten places, and the two `hasPersistentIndex` / `denseRouteOf` reaches mean the bench encodes adapter taxonomy knowledge outside the seam. Individually every import is defensible (importing `fitToTokenBudget` rather than restating it is *correct* — `run.ts:servedAtoms` says so and is right). Collectively they falsify the docblock, which is the load-bearing claim a reader routes on.

**Recommendation** — pick one, do not do both:
1. Make it true: re-export what the bench legitimately needs (`fitToTokenBudget`, `RERANK_K_INIT`, `DEFAULT_PRF_PARAMS`, `fusesLegs`, `readIndexAnalyzer`, …) *through* `engine.ts`, and add an `eslint` `no-restricted-imports` rule forbidding `../../gnosis/src/**` outside `src/engine.ts`. This is the version that buys replaceability.
2. Or correct the claim: rewrite the docblock and the GUIDE row to say `engine.ts` owns the **measured retrieval path** (ingest → index → port → retrieve → rerank) and that constants/types are imported directly by design, then add the lint rule restricted to `adapters/**` and `cli/**` only. Cheaper, honest, and still stops the worst reaches.

#### H2 — `flags.ts:assertKnownFlags` guards 4 of 11 entry points; the other 7 silently ignore an unknown flag

Verified by grep across `packages/gnosis-bench/src`: `assertKnownFlags` is called by `run.ts:parseArgs`, `sweep.ts`, `externalScore.ts`, `pair.ts` — and by nobody else. `forensicsCli.ts`, `goldAuditCli.ts`, `vocabGapCli.ts`, `fuseForecastCli.ts`, `charts.ts`, `enrichmentGate.ts` and `deterministicEnrichment.ts` each hand-roll a `flagValue` reader and drop an unrecognised token without a word.

`flags.ts`'s own docblock names this as the failure class it exists to kill. So `npm run gnosis:forensics -- --run X --kk 20` runs at the default cut and reports the result as measured under a flag the operator believes they set.

**Recommendation**: add a `FlagSpec` + `assertKnownFlags(argv, SPEC)` line as the first statement of each of the seven parsers. `flags.test.ts` already asserts a spec against its call sites for `run.ts`; extend that test to the other specs so a flag added without a spec entry fails the suite.

#### H3 — Three analysis tools can produce an empty or all-zero artefact and exit 0

The project's stated failure class is *"a component produced nothing, and the pipeline recorded it as data."* The core refuses this rigorously (see Strengths). The periphery does not:

| Site | Mechanism |
|---|---|
| `vocabGapCli.ts:readTopics` + `serialize` | `readTopics` refuses only *malformed* lines (`bad.length > 0`). An empty or all-blank `queries.jsonl` yields `topics = []`, `bad = []`, no refusal; `serialize([])` returns `"\n"`, which is written and exits `VOCAB_GAP_EXIT_OK`. Zero topics measured, recorded as a successful measurement |
| `goldAuditCli.ts:requireRunFile` | Checks `existsSync` only. A present-but-empty `.trec` gives an empty ranking map → `depthOf` → `0` → every topic scored at depth 0 → the report prints a confident `nDCG@10 0.0000` under both qrels columns. `emptyRankingLines` does surface the count in prose, but the metric cells still print a number rather than the empty cell the file's own rule mandates |
| `goldAudit.ts:auditGold` | No guard for `corpusDocs === 0` or zero relevant judgments; an empty corpus yields an all-zero audit block at exit 0 |
| `chartData.ts:armBars` / `pointsOf` | Missing metrics are `flatMap`-ed away: a run lacking every requested metric draws an empty group / empty polyline **with a legend entry**, at exit 0 |

**Recommendation**: give each tool the `engine.ts:assertPortSound` treatment — a named `error.cause` refusal when the measured set is empty. `engine.ts:assertIngestSound` and `assertPortSound` are the pattern; they are already exported as separately-testable fact objects and should be copied, not re-invented.

### MEDIUM

#### M1 — `PROVENANCE_FIELDS` is enforced by convention, not structurally. `compare.ts:SCALE_FIELDS`/`TREATMENT_FIELDS`, `report.ts:RunProvenance`

`compare.ts` is the best-argued module in the package and its refusal logic is correct. But the guarded set is a hand-written literal:

```ts
export const TREATMENT_FIELDS = ['adapter', 'rerank', /* …23 more */ ] as const;
```

`ProvenanceChange.previous: HistoryRow[ProvenanceField]` gives one direction of safety — a name in the list must be a key of `HistoryRow`. **The other direction is unguarded**: adding a new treatment to `RunProvenance` and stamping it in `run.ts:provenanceOf` does *not* fail typecheck, does *not* fail any test, and produces a run whose new arm is silently subtracted as a like-for-like delta. Coverage is currently maintained by a per-feature test convention (`expect(TREATMENT_FIELDS).toContain('bodySource')` in `tests/bodySource.test.ts`, and eight more like it) — discipline that has held so far and that nothing enforces.

Note the package already uses the right idiom elsewhere: `report.ts` writes `] as const satisfies readonly (keyof Metrics)[]` for three column lists.

**Recommendation**: split `RunProvenance` into `ProvenanceIdentity` (`ts`, `gitSha` — deliberately unguarded) and the guarded remainder, then assert exhaustiveness at the type level, e.g.

```ts
type Guarded = Exclude<keyof RunProvenance, 'ts' | 'gitSha'>;
const _exhaustive: readonly Guarded[] = PROVENANCE_FIELDS;   // fails to compile if a field is missing
```

A new provenance field then cannot be added without classifying it as scale or treatment.

#### M2 — Four engine-facing docblocks cite a mechanism that has been dead since T6.2

`GNOSIS-GUIDE.md` § Landmines records the frozen-`ATOM_DOMAINS` landmine as **MECHANISM DEAD**: the index-side `asDomain` re-check was removed, and `grep -rn asDomain packages/gnosis/src/` reaches only `bench.ts:asDomain` (an unrelated query-side helper) — **no adapter**. Four bench sites still state it as live:

- `engine.ts` docblock rule 4: *"`fts5Adapter.asDomain:127` narrows against it, so an atom carrying an off-vocabulary domain is DROPPED at index time"*
- `engine.ts:emptyIndexMessage` — the operator-facing text: *"the usual cause is an ingest profile declaring a domain outside the frozen ATOM_DOMAINS vocabulary … Use the shipped `docs` domain"*
- `engine.ts` `ingestAndProbe` docblock: *"the fact it proves, that ingest survived the frozen `ATOM_DOMAINS` narrowing"*
- `corpus.ts` header: *"`config.ts` freezes `ATOM_DOMAINS` at import time and `fts5Adapter.asDomain` narrows against it"*

The **assert is still right and must stay** — `GNOSIS-GUIDE` says so explicitly ("the RULE survives its mechanism"). What is wrong is the diagnosis it hands an operator: the message sends them to change a domain that is no longer the cause, so a real empty index gets misattributed.

**Recommendation**: keep `assertIngestSound` unchanged; rewrite `emptyIndexMessage` to state the fact (zero atoms indexed after a successful ingest) and list causes without asserting one, and correct the three docblocks in place per the handbook's "a superseded claim MUST be corrected in place" rule.

#### M3 — Exit-code semantics diverge across tools

Per `CLAUDE.md` § Exit-Code Contract, `3` means "refused / state mismatch". Measured:

| Tool | Refusal code | Notes |
|---|---|---|
| `run.ts` | `REFUSAL_EXIT_CODE = 3`, gate `4` | correct, documented in `RUN_HELP` |
| `forensicsCli.ts` | `FORENSICS_EXIT_REFUSED = 3` | correct |
| `fuseForecastCli.ts` | `FUSE_FORECAST_EXIT_USAGE = 2` | `assertProvenanceMatch` / `assertReproduces` are state mismatches reported as usage errors |
| `charts.ts` | `CHARTS_EXIT_USAGE = 2` | a refused paired test reported as a usage error |
| `vocabGapCli.ts`, `goldAuditCli.ts`, `enrichmentGate.ts`, `deterministicEnrichment.ts` | `2` for everything | one top-level `catch` collapses every failure — including `forensics.ts:MALFORMED_RUN_LINE_CAUSE`, a corrupt input — into "usage" |

A caller (or an agent following the exit-code contract) cannot distinguish "you typed it wrong" from "the data is not what you think it is". That distinction is the whole point of the contract.

**Recommendation**: adopt one code table across the package — `0` ok, `2` usage, `3` refused/state-mismatch, `4` gate failed — and branch on `error.cause` (every refusal already carries a named cause constant) rather than collapsing in one `catch`.

#### M4 — Result/error shape inconsistency across the four analysis tools

`forensicsCli.ts` returns a discriminated `ForensicsOutcome`; `goldAuditCli`, `vocabGapCli`, `fuseForecastCli` throw and catch at `main`. `forensicsCli` renders a missing cell as `'n/a'` while `forensicsCell`, `goldAuditCli:cell` and `fuseForecast:cell` render it empty. Repeated flags: `forensicsCli` / `fuseForecastCli` take the **first** occurrence (`argv.indexOf`), `goldAuditCli` / `vocabGapCli` take the **last** (`.at(-1)`). `vocabGapCli` alone prints help to **stdout** and exits 2 on a missing flag without naming it.

`COMMON.md` §V makes interface consistency non-negotiable for exactly this surface.

**Recommendation**: extract a small `src/cli/` module inside the bench holding `flagValue`, `messageOf`, `invokedDirectly`, the cell formatter and the exit table — `messageOf` and `invokedDirectly` are currently duplicated 11× each. This is a genuine ≥2-consumer helper set under `COMMON.md` § Code Placement, not speculative abstraction.

#### M5 — `manifest.ts:parseManifest` validates known keys and silently accepts unknown ones

The validator is otherwise excellent — total over the format union, every failure names a fix, `layers` is required so a new entry cannot join no layer by omission. But `toEntry` / `beirOf` / `brightOf` / `milqaOf` read named keys and never reject extras. A typo'd `"atomMaxChar": 6000` is dropped in silence; `run.ts:effectiveAtomMaxChars` then records the engine default and the row is stamped as if the operator's value were in force — a *scale* field, mis-stamped, which is precisely what `compare.ts` exists to protect.

**Recommendation**: after building an entry, compare `Object.keys(record)` against the allowed key set for that format and `fail()` on a surplus, with the same fix-naming message style.

#### M6 — Duplicated measurement rules

`entry.format === 'bright' ? 'test' : entry.qrels` appears 5×; `entryFor` 3×. Which split a format is scored under is *provenance*: five copies is five places for it to rot, and `GNOSIS-RULES.md` § Volatile facts forbids exactly this shape of restatement.

**Recommendation**: one exported `qrelsSplitOf(entry)` in `manifest.ts` (the manifest's owner), imported everywhere.

#### M7 — `chartSvg.ts` carries 45 % of the package's style debt and no test

Measured (`npx eslint packages/gnosis-bench/src`, 2026-08-31): **0 errors, 165 warnings**. Distribution:

| Rule | Count |
|---|---|
| `no-magic-numbers` | 116 |
| `max-params` | 18 |
| `max-lines-per-function` | 14 |
| `complexity` | 14 |
| `no-restricted-syntax` | 3 (all `lines.ts`, all justified) |

By file, `chartSvg.ts` alone carries **74 of 165**. The chart stack is 966 lines across `charts.ts` / `chartSpec.ts` / `chartData.ts` / `chartSvg.ts`, is standalone (`gnosis:charts`, never invoked by `run.ts`), and has **one** test file (`tests/charts.test.ts`) covering four modules — `chartData`, `chartSpec` and `chartSvg` have none of their own, against a package norm of one test file per source module (30 test files / 35 sources).

**Recommendation**: this is the package's clearest candidate for subtraction. Either give `chartSvg.ts` a named-constant pass plus its own test, or ask whether an SVG renderer hand-written inside a benchmark earns 363 lines when the underlying data (`chartData.ts:buildCharts`) is already a clean typed structure that any external plotter could consume. Do not extend it before answering that.

### LOW

- **L1 — No public API boundary.** 512 exported symbols across `src/`, no `src/index.ts` barrel, and ~180 of them have no consumer outside their defining file (`compare.ts:MetricDelta`, `metrics.ts:averagePrecision`, `run.ts:CliOptions`, `chartData.ts:runCaption`, …). Much of this is export-for-test, which is legitimate — but with everything exported, `export` no longer signals "public", and `COMMON.md` § Module Encapsulation asks for a stated boundary. Cheapest fix: nothing structural, just stop exporting new internals by reflex; the honest fix is a barrel naming the ~40 symbols that are genuinely cross-module.
- **L2 — `externalScore.ts` (411 lines) has no npm script and no README entry.** Root `package.json` wires ten bench tools; this is not one of them. `README.md:94` describes the external-arm workflow conceptually but never names the file or how to run it. A well-built, tested (`tests/externalScore.test.ts`) tool that an operator cannot discover.
- **L3 — `forensicsCli.ts:ForensicsOutcome.cause` is write-only.** `emit` branches on `kind` only; `CAUSE_NO_RUN_PATH`, `CAUSE_NO_PER_TOPIC`, `CAUSE_ATOMS_NEWER_THAN_RUN` have zero references anywhere, tests included. Three refusal paths untested and their discriminant unread. `CAUSE_ATOMS_NEWER_THAN_RUN` is the stale-cache landmine's own guard — the one most worth a test.
- **L4 — Silent-zero fallbacks in `fuseForecast.ts`.** `fusedScore`'s `weights[index] ?? 0` drops a leg's contribution; `fusionArm`'s `aligned[index] ?? new Map()` fuses an empty ranking. Both are currently unreachable (`fusionSpecs` hardcodes the indices) but they degrade toward a plausible number rather than throwing — the shape the project's failure class warns about.
- **L5 — `charts.ts` header contradicts its code.** The docblock promises exit 2 means "nothing was drawn"; `regenerate` builds all charts before writing, which covers build failures only. A write failure mid-`map` leaves earlier SVGs on disk — the half-regenerated set the docblock forbids.
- **L6 — One unsafe cast in the package**: `vocabGapCli.ts:toTopic` does `JSON.parse(line) as Readonly<Record<string, unknown>>`. `chartSpec.ts:readChartsSpec` shows the safe idiom (`const raw: unknown = JSON.parse(...)`) two files over.
- **L7 — `score.ts:scoreDataset` falls back to `EMPTY_QREL`** for a topic absent from the qrels, scoring it all-zero. Currently unreachable — `run.ts:topicsOf` derives topics *from* `qrels.keys()` — but the guard depends on a caller invariant rather than on the function. A named refusal would cost one line.
- **L8 — Function-length / parameter-count metrics.** `run.ts:parseArgs` is ~50 lines and `provenanceOf` ~27 against `COMMON.md`'s 20-line maximum. Both are flat, total, single-purpose constructions of a wide options object, so decomposing them would likely make them worse; noted for completeness, not recommended for change.
- **L9 — `fetch/*` divergence.** Byte-size cache verification exists only in `bright.ts:isCached`; gold-vs-corpus coverage only in `vault.ts:assertGoldReachable`. `bright.ts:readShard` and `milqa.ts` return `[]` on a schema change, after which `existsSync` latches the empty dataset permanently — the stale-untracked-cache landmine, one layer down.

## Strengths

These are not filler; they are the reason the verdicts above are as narrow as they are.

1. **`run.ts` and `engine.ts` are exemplary against the project's own failure class.** `assertCorpusMaterialized`, `assertIngestSound`, `assertGoldIndexed`, `assertIndexArtefact`, `assertPreparedFor`, `assertPortSound`, `probePortSoundness`, `assertRerankDiscriminates` form a layered gauntlet in which *every* guard is a POSITIVE check against a recorded fact rather than an error-string match, each carries a named `error.cause`, and each message explains what the all-zero row would have looked like if the guard had not fired. `assertRerankDiscriminates` in particular defends against the hardest case — a reranker that answers HTTP 200 with document-independent scores — which nothing downstream could see.

2. **`compare.ts` is the best-argued module in the repository.** The scale/treatment split, the `appliesTo` predicate (so `rerankPool` cannot swallow rerank-on-vs-off), and the `FIELD_DEFAULTS` backfill — each entry justified against the recorded rows it would otherwise relabel — encode a real, expensive lesson as a refusal. `significance.ts:pairedSignificance` reuses the same guard rather than re-deriving it, and `pairedScores` refuses an inner join on mismatched topic sets.

3. **The functional discipline is real, not aspirational.** Zero eslint errors over 14 068 lines; the single imperative loop in the package (`lines.ts:foldChunks`) is there because a 0.69 GB corpus exceeds Node's string cap, and it says so with the measurement. `collect`'s `push` carries the O(n²) argument for why the spread was unusable at 382 545 lines.

4. **Incremental recording defends against process death.** `measureAndRecordAll`'s docblock cites the 2026-08-15 OOM that lost six completed datasets, and records each the moment it finishes. `attempt` records *inside* the try, so "measured but not written" cannot count as recorded. `selectionError` refuses an empty selection rather than exiting 0 on zero datasets.

5. **Constants have single owners and the code says where.** `bench.sh` owns the heap limit and states why `gnosis:sweep` is deliberately excluded; `RUN_HELP` documents the exit codes and routes the flag table to the README rather than restating it; `INDEX_SUFFIXES` is total over `AdapterName` so a new adapter cannot be measured until its path is declared; `run.ts:fuseLegAtoms` imports `fuseForecast.ts`'s own `rrfScored` so the route and its offline forecast cannot diverge on arithmetic.

6. **`manifest.ts` validation is total and fix-naming.** Every failure message names the repair, `layers` is mandatory-but-possibly-empty by design, and `parseManifest` refuses a non-object root rather than reading `undefined.datasets`.

7. **Test discipline.** 30 test files against 35 sources, near one-to-one, with the guards exported as separately-testable fact objects (`IngestSoundness`, `PortSoundness`, `CorpusMaterialization`) precisely so they can be exercised without staging a corpus that indexes nothing.
