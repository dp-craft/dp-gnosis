## Blocking findings (fix before calling it shippable)

1. **`mcp/server.ts:onLine` discards rejected promises** — `void emit(...)` with no `.catch`; any throw outside the two tagged error kinds kills the process with no JSON-RPC response for the pending id. The project's own failure class ("a component produced nothing, and the pipeline recorded it as data") on its least observable surface.
2. **`cli/main.ts:main` has no error boundary** — an escaped throw exits 1 (produced nowhere in source, documented nowhere) with a raw `dist/` stack trace, outside the 0/2/3 vocabulary the README tells callers to branch on.

## High-priority findings

3. **The bench seam is fiction as enforced** — `gnosis-bench/engine.ts` claims to be the only contact with the engine; 10 files import 15 engine modules directly (deep relative paths, never the barrel). Either route through the seam and add `no-restricted-imports`, or correct the docblock and the GUIDE row. (bench review, HIGH-1)
4. **Silent flag acceptance on both CLIs** — engine `cli.ts:SCOPE_CHECKS` lets `--rerank-pool`, `--no-prf`, `--golden-set`, `-k` be accepted-and-ignored on any command (verified: `doctor --rerank-pool 5` exits 0); bench-side, 7 of 11 entry points never call `flags.ts:assertKnownFlags`. Same defect, both packages. (cli F3, bench HIGH-2)
5. **Four bench tools emit empty/all-zero artefacts at exit 0** — `vocabGapCli` serializes zero topics, `goldAuditCli` scores an empty `.trec` as a confident `0.0000`, `goldAudit` has no zero-corpus guard, `chartData` draws an empty series. Direct instances of the stated failure class. (bench HIGH-3)
6. **`linearScanAdapter.ts` contains a raw NUL byte** (`MANIFEST_SEPARATOR` literal) — `file` classifies it as data and every grep silently skips the file. This already produced a false handbook claim: `fromAtom` still drops unknown-domain atoms, contradicting the landmine row that says no adapter does. (engine S1)
7. **The llama-swap client is quintuplicated** — `chat.ts`, `rephrase.ts`, `synthesize.ts`, `embed.ts`, `rerank.ts` each redefine endpoint, catalogue fetch and refusal messages; only `rerank` bounds its timeout, the other three hang on an unreachable host. (engine S1)
8. **Wizard preset flow** — after a preset computes the answers, `flow.ts:askMatching`/`askCorpus` still present 7-row expert menus (4 rows say "don't pick me"; `lancedb-vec` is measured harmful); `askRoot` re-asks forever with no cancel, a defect already fixed once in `rerankFlow.ts:askPort`. Collapse to confirmations under a non-`custom` preset. (cli F1, F2)

## Medium-priority themes

- **Doc rot in code-adjacent docblocks**: four bench docblocks (incl. the operator-facing `emptyIndexMessage`) still diagnose the dead `asDomain`/frozen-`ATOM_DOMAINS` mechanism; `ingest.ts` carries three stale citations incl. a "single-column fts5" claim; GNOSIS-GUIDE's vitest landmine prescribes a `vitest.tools.config.ts` that does not exist.
- **The author's previous machine ships in the product**: `config.ts:CORPUS_ROOTS` names the old repo's layout (fresh install → bare `ingest` exits 2 on paths the user never saw); `AUTHORING.md` and `CONFIGURATION.md` §7.2 document `/home/dev/work/aichatney/...` and constants that no longer exist.
- **Resource/robustness details**: six sqlite handles closed outside `try/finally`; `paths.ts` does `existsSync` at import, falsifying `config.ts`'s purity claim transitively; O(n²) `duplicatesOf`/`partSuffix` in ingest.
- **Unfalsifiable lint gate**: `npm run lint` exits 0 at 306 warnings; ratchet with `--max-warnings`.
- **Dead code**: `buildQuery` + `QueryInput` + `QUERY_MAX_TERMS` (no production caller, duplicate IDF), `footnotes.ts` (test-only), 13 zero-consumer deprecated `paths.ts` constants, two of three wizard-detected backends never consumed.
- **Provenance enforced by convention**: adding a field to `RunProvenance` fails no typecheck; a `satisfies`-exhaustiveness assertion (the idiom `report.ts` already uses) closes it.
- **CLI policy extraction (proposal)**: move pool/floor/budget/confidence policy out of `retrieveCommand.ts` into a service module so `index.ts:search` and MCP stop round-tripping through argv + `as GnosisAnswer`.

## What is genuinely strong — preserve it

- **FP discipline and naming** — uniformly strong across 133 files; the codebase reads without comments, as intended.
- **Refusal semantics** — refuse-with-remedy instead of silent fallback (`openPort` digest mismatch, `resolveRerankFusion`, catalogue refusals) is the product's best idea and is implemented consistently on the core path.
- **Configuration layering** (env > config.json > defaults) rated strong; external-service coupling degrades gracefully with actionable refusals.
- **Interface/doc fidelity** — an independent cross-check found zero flag/command/exit-code/env-var mismatches between README/CONFIGURATION and `args.ts`.
- **Gates are real**: `npm run typecheck` exit 0, CI is a 2×2 matrix running the suites sequentially plus `npm pack --dry-run`.

## Reading of the whole

The core retrieval path is in better architectural shape than the periphery. Every weak rating traces to one of two patterns: **a documented boundary nobody enforces mechanically** (the bench seam, the CLI scope lists, provenance fields) or **accumulated periphery the core discipline never reached** (duplicated HTTP clients, dead modules, tools that exit 0 on nothing). Both are cheap to fix relative to the quality of what they surround; neither requires touching ranking behavior, so none of the fixes needs a benchmark gate except where a docblock correction touches governance files.
