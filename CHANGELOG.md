# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Measured retrieval-quality numbers are **not** recorded here. They live in `handbook/GNOSIS-BASELINES.md`, where each row carries its corpus, serving config and sha — the three things that make a quality number a fact rather than a recollection.

## [Unreleased]

### Changed

- **`packages/gnosis/README.md` split into three: the CLI reference plus `QUERYING.md` and `OPTIONAL.md`.** The README had grown to 774 lines, so a reader looking up one flag read past the rephrasing rules, the agent tool prompt, the reranker setup and the dense/hybrid routes to reach it. § Query rephrasing and § LLM integration prompt MOVED verbatim to `QUERYING.md`; § Setting up the reranker and § Dense and hybrid research routes MOVED verbatim to `OPTIONAL.md` — no section exists in two files, and the README now opens with a routing table naming each sibling and the question it owns. § Flags stayed put: it IS the CLI contract, and `tests/readmeFlags.test.ts` locks it against `FLAGS` in both directions, unchanged. Both new files are added to `paths.ts:DEMO_CORPUS_ROOTS` and `package.json`'s `files`, so `demo` still ingests the whole of this package's documentation rather than silently dropping the moved half.
- **BREAKING — the retrieval verbs are renamed: `retrieve` → `search`, `answer` → `ask`, and the MCP tool `gnosis_answer` → `gnosis_ask`.** A deliberate pre-1.0 break with **no aliases, no deprecation shim and no compatibility mapping**: the old verbs stop working. `dp-gnosis retrieve "…"` now exits **2** with the existing unknown-command message, which lists the valid commands and so names `search` itself — that is the whole migration path. The `--json` `command` field reports the new verb (`search` / `ask`), and every refusal that names its command (`search: …`, `ask` refusing `--flat`) does too. File names and exported symbols (`retrieveCommand.ts`, `runRetrieveCommand`, `answerCommand.ts`, `runAnswerCommand`) are internal and unchanged.
- **Renamed the published package `@dp/gnosis` → `dp-gnosis`.** The `@dp` npm scope belongs to a third party and already publishes unrelated packages, so the package as previously named could not be published at all. `bin` was already `dp-gnosis` and is unchanged. `isInstalled()` matches the `node_modules` path segment rather than the package name, so install-path resolution does not move, and no TypeScript file imported the package by name. **Downstream consequence, not fixed here:** the AiChatney runner's `@dp/gnosis` seam was already broken before this rename; its repair must now target `dp-gnosis`.
- **`minisearch` moved from `optionalDependencies` to `dependencies`; `@lancedb/lancedb` and `apache-arrow` moved to `devDependencies`.** npm installs `optionalDependencies` by default, so a tool whose front page says "no embeddings, no cloud" was downloading a 313 MB vector database into every install. `minisearch` (904 KB) backs a shipped lexical adapter and is now a plain dependency. The dense/hybrid routes stay reachable through `--adapter`; their dependencies are installed for development only. Both lancedb adapter suites still build real indexes against the workspace copies — **no skip guard was introduced**, because a silently skipped adapter suite is this repository's own failure class.
- `.github/workflows/ci.yml` runs a matrix: `ubuntu-latest` and `macos-latest` × Node 22 and 24, `fail-fast: false`. The two test suites remain **sequential steps within a job** — they share a work directory. `node-version-file: .nvmrc` was dropped from CI so the matrix is the single owner of the version; `.nvmrc` stays the local default.
- `packages/gnosis/INTEGRATION.md` documents the **installed** MCP and CLI launch forms beside the existing checkout forms, following the installed-vs-checkout distinction `src/invocation.ts` already owns.
- Flattened `tools/dp-gnosis/` and `tools/dp-gnosis-bench/` into `packages/gnosis/` and `packages/gnosis-bench/`. The AiChatney-mirroring layout is gone. `packages/gnosis/src/` sits three levels below the repo root exactly as the old path did, so `paths.ts:repoRoot()` and the profile JSONs' `../../../` anchors resolve unchanged.
- Adopted npm workspaces with a single root lockfile, replacing three separate installs. Resolved versions of `better-sqlite3` (the FTS5 tokenizer) and `stemmer` (applied via `processTerm` to every adapter) were captured before and after hoisting and are unchanged, so ranking cannot have moved.
- Renamed the runtime data root `dp-gnosis/` to `benchmark-data/`.
- Moved the benchmark suite from colocated `src/*.test.ts` into `tests/`, matching the engine's convention. Same 30 files, same 773 tests.
- Collected the six `GNOSIS-*.md` governance files into `handbook/`, filenames unchanged so their mutual references keep resolving.
- The benchmark's `tsconfig.json` now includes `tests/` and `scripts/`, and `npm run typecheck` runs it. Neither had ever been typechecked by any script.

### Added

- **`update` — `ingest` then `index` as one command.** They are one operation in two commands and the second is the routinely forgotten half; an `ingest` alone leaves the index carrying the old digest and the next query refuses. `update` exits with the **more severe of the two hops**: an `ingest` that exits 3 (files skipped, each with a reason) followed by an `index` that exits 0 makes `update` exit **3**, not 0 — `EXIT_PARTIAL` already means "real output was produced AND something was refused", and a caller reading 0 would never learn files were skipped. An `ingest` that exits **2** stops the command before `index` runs, because there is nothing to index and the second failure would bury the first. Both hops are reported: `--json` carries `ingest` and `index` under their own keys (`index` is `null` when it never ran). It honours the union of both commands' flags and adds none. Neither hop is re-implemented — the handlers are composed.
- **`demo` — a ranked result for a reader who owns no corpus.** It ingests, indexes and searches gnosis's own shipped documentation (every `.md` named by `paths.ts:DEMO_CORPUS_ROOTS`, resolved from the package directory, so it works in a checkout and an install alike) and prints the hits. Its data lives in a **fixed, isolated `demo/` subtree under the resolved data root** — `<dataRoot>/demo/atoms` and `<dataRoot>/demo/index/` — and it can never use the default atoms or index paths: `ingest` writes AND prunes, so a demo pointed at the defaults would claim and prune a real vault on the one command whose promise is that trying it costs nothing. Re-running it is idempotent. Exit 0 means it produced hits; producing none is reported as a FAULT at exit 3, never as a quiet 0. Like `init`, it is exempt from the declared-`repoRoot` check. It runs as a shipped `demo` profile, and `packages/gnosis/package.json`'s `files` now ships every one of those documents rather than the README alone, so an installed demo has a real corpus.
- `README.md` repositioned around what the measurements actually show: **it finds the exact identifier vector search misses**, rather than the negative "no embeddings". Adds § Why not ripgrep? (an honest split — a string you can spell exactly is `rg`'s job) and § Measured against a vector-hybrid tool, carrying the `tobi/qmd` 2.8.3 head-to-head with its corpus, serving config and `gitSha` `e468b2bd`, its three caveats (qmd is not run-to-run reproducible, two corpora both the author's, qmd untuned) and a route to `handbook/GNOSIS-BASELINES.md`, which owns the numbers. CI, licence and Node badges.
- **`dp-gnosis-mcp` bin**, pointing at `dist/mcp/main.js`. The MCP server was previously reachable only through the root workspace script `npm run gnosis:mcp`, so an installed user could not serve MCP at all. `src/mcp/main.ts` gained the `#!/usr/bin/env node` shebang its new role as a bin target requires — npm symlinks a bin rather than wrapping it.
- **`--version` / `-v`**, printing the version from the package's own manifest and exiting 0. It is answered before any config or profile is read, so it survives a malformed `config.json` exactly as `--help` does, and it outranks `--help` when both are passed. The version is never duplicated in TypeScript.
- **`doctor` now runs the rerank discrimination probe.** A reranker that is not configured or not reachable is `unknown` at **exit 0** — reranking is opt-in and its absence is not a defect, and the catalogue call that establishes it is bounded so an offline pass cannot hang. A reachable reranker that FAILS the probe is a `fault` at **exit 3**, carrying the probe's own refusal verbatim. One that passes reports `ok` with both raw probe scores. No second probe was built: the check calls the same `src/rerank.ts` probe the serving path and the benchmark call, through the same per-process memo, so it doubles as the cold-load warm-up.
- `os: ["linux", "darwin"]` in `packages/gnosis/package.json`. Linux is the support contract; macOS is best-effort. Windows is unsupported and now says so.
- `README.md` carries the real clone URL (`https://github.com/dp-craft/dp-gnosis.git`) in place of the `<this-repo>` placeholder that made step 1 of the install unfollowable, plus a `--version` verification line and a note on `better-sqlite3` being a native build.
- `packages/gnosis/OPTIONAL.md` § Setting up the reranker — the OpenAI-compatible `/v1/rerank` contract, the two GGUF repos confirmed working and the ones known broken. Most published Qwen3-Reranker GGUFs are missing the `cls.output.weight` head and score every pair at ≈4.5e-23 while answering 200: `handbook/GNOSIS-RULES.md` § The failure class on the serving path, previously undocumented anywhere a user would look.
- `README.md` § What that actually looks like — real captured terminal output for `ingest` / `index` / `retrieve`, including the skip refusals and the `confidence weak` verdict, rather than a described result.
- `packages/gnosis/OPTIONAL.md` § Dense and hybrid research routes — what the three dense/hybrid `--adapter` values are, the (verified) command that installs their dependencies, and where their measured verdict lives. The adapter docblocks in `src/adapters/miniSearchAdapter.ts` and `src/adapters/lanceDbAdapter.ts` were corrected in place: both still described their package as an `optionalDependency`, a field this release deletes.
- `init` and `doctor` rows in `packages/gnosis/README.md` § Commands. Both commands have existed since 0.1.0 and the root README depends on both; the **flag** table is test-locked in both directions, the **command** table was not.
- `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `SECURITY.md`, this changelog, `.editorconfig`, `.nvmrc`.
- `license: GPL-3.0-or-later` in all three manifests. They previously declared none, so npm reported UNLICENSED for a GPL project.
- GitHub Actions CI running typecheck, lint, and the two suites — sequentially, in that order.

### Fixed

- **The public repository routed readers to files it does not ship.** `.gitignore` carries `docs/`, so the `docs/analysis/…` and `claude-artifacts/…` citations throughout `handbook/` name files a cloner will never have — 25 of them in `GNOSIS-HISTORY.md` alone. The citations are provenance and `GNOSIS-RULES.md` § Evidence requires a number to carry its source, so they stay; the boundary is now STATED once in `handbook/GNOSIS-GUIDE.md`, with `GNOSIS-BASELINES.md` and `GNOSIS-HISTORY.md` routing to it rather than restating it.
- **The rerank discrimination probe passed a GGUF that had produced nothing.** `probeSignature` was DIRECTIONAL ONLY — it asked whether the relevant probe passage outscored the irrelevant one and nothing else — so a GGUF converted without the `cls.output.weight` rank head, which scores every pair at ~4.5e-23, was called healthy whenever the relevant score landed a hair higher (`relevant = 4.6e-23, irrelevant = 4.5e-23`). That is the `mradermacher/Qwen3-Reranker-*-GGUF` and `DevQuasar/*` family (upstream ggml-org/llama.cpp#16407), and it is `handbook/GNOSIS-RULES.md` § The failure class exactly: a component produced nothing and the pipeline recorded it as data. A third signature, `DEGENERATE`, now refuses a relevant score below the owner-approved `RERANK_PROBE_MIN_SCORE = 1e-6` (`src/config.ts`) — read BEFORE the direction, because a degenerate pair is directionally correct half the time. A working model scores near 1.0, so the floor sits ~17 orders of magnitude clear of both populations and needs no calibration. `CONSTANT` and `INVERTED` are unchanged, and every refusal still quotes both raw scores verbatim.
- **`demo` silently ignored `--atoms-dir`, `--index-path`, `--repo-root` and `--profile` under exit 0.** `demo --atoms-dir /tmp/x` ranked hits, wrote nothing to `/tmp/x` and said nothing — the silently-dropped-token failure `src/cli/args.ts` exists to refuse. `demo` owns fixed paths by construction (`paths.ts:demoAtomsDir` / `demoProfilePath`), so the four are now refused at **exit 2** through the same `misplacedFlag` + `unknownFlagMessage` path every other misplaced flag takes — a per-command refusal list, not a special case inside the handler. `--adapter`, `--json` and `-k` are still honoured, and all four still resolve normally on every other command.
- `README.md` claimed the three dense/hybrid routes "are deliberately not shipped" while `--adapter lancedb-hybrid-full` was wired through `src/cli/args.ts`, `src/cli/indexCommand.ts` and `src/cli/doctorCommand.ts`. The routes ship; their dependencies do not.
- `README.md` said "The six rules" of query rephrasing while the list it pointed at, `packages/gnosis/QUERYING.md` § Query rephrasing, has five.
- `npm run lint` exits 0. It first failed at 59 errors; it had since drifted back to **17 `simple-import-sort/imports` errors** across 14 files, which meant the CI Lint step was red on `main`. Cleared with `eslint --fix`: import ordering and trailing commas only, plus one equivalent quote-style normalisation in a SQL string literal in a test. No assertion and no behaviour changed.
- `packages/gnosis-bench/scripts/crossPair.ts` and `materialize-beir.ts` imported with `.ts` specifiers (TS5097), against the `.js` convention used everywhere else. Invisible until `scripts/` was typechecked for the first time.

## [0.1.0] — 2026-08-24

### Added

- Extracted the engine and its benchmark from AiChatney into a standalone repository, so the quality gate lives beside the code it gates. The directory shape deliberately mirrored the source repository so `REPO_ROOT` still resolved and the extraction needed no code change — which is what made its byte-identity gate meaningful.
- `@dp/gnosis` published surface (renamed to `dp-gnosis` in Unreleased): `exports` map, `bin`, `files`, and the `./mcp` subpath carrying the MCP argv contract.

### Changed

- **`gitSha` changed meaning on this date.** Every benchmark row is stamped with this repository's sha; rows recorded before the extraction name commits that do not exist here. `handbook/GNOSIS-GUIDE.md` § Current measured state carries the boundary and the mapping.
